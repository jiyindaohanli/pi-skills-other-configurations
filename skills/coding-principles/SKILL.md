# 编码四原则（强制遵守）

对 sso、form-submission、devops-system 三个项目的任何代码修改，必须严格遵循以下原则。

## 1. 编码前思考

- 明确说明假设 — 如果不确定，询问而不是猜测
- 呈现多种解释 — 当存在歧义时，不要默默选择一种
- 适时提出异议 — 如果存在更简单的方法，说出来
- 困惑时停下来 — 指出不清楚的地方并要求澄清

## 2. 简洁优先

- 不要添加要求之外的功能
- 不要为一次性代码创建抽象
- 不要添加未要求的"灵活性"或"可配置性"
- 不要为不可能发生的场景做错误处理
- 如果代码可以更短，重写它

**检验标准：** 资深工程师会觉得这过于复杂吗？如果是，简化。

## 3. 精准修改

- 不要"改进"相邻的代码、注释或格式
- 不要重构没坏的东西
- 匹配现有风格，即使你更倾向于不同的写法
- 如果注意到无关的死代码，提一下 — 不要删除它

当你的改动产生孤儿代码时：
- 删除因你的改动而变得无用的导入/变量/函数
- 不要删除预先存在的死代码，除非被要求

**检验标准：** 每一行修改都应该能直接追溯到用户的请求。

## 4. 目标驱动执行

- 将任务转化为可验证的目标
- 对于多步骤任务，先说明计划再执行
- 每次修改后验证结果
